# 读音修正

目标：字幕永远显示正确的字，配音念对的音。两者分开存、分开改。

## 分层

从字幕到送给 TTS 的文字，中间有三层，越往后越只影响配音：

| 层 | 在哪 | 管什么 | 例子 |
| --- | --- | --- | --- |
| `text` | `video/src/script/ep*.ts` 的每一句 | 字幕，也是默认念法 | `LoRA 权重默认 0.7` |
| `tts` | 同一句的可选字段 | 这一句的念法和字幕不同 | `LoRA 权重默认零点七` |
| `spokenText()` | `video/scripts/spoken-text.ts` | 对所有句子统一生效的改写 | `×` → 乘，重绘 → 虫绘 |
| 引擎写法表 | 换了引擎才需要，比如 `lexicon.json` | 只给某个 TTS 看的写法 | `XL` → `叉L` |

`spokenText()` 又分两部分：

- `readingText`：真人来念也会这么念的改写，比如去掉「」、`×` 念「乘」、缩写逐个字母念。提词稿也用这一层。
- `pinPolyphones`：只给 TTS 的多音字修正，真人照原字念就行。

## 多音字：用同音字钉死

edge-tts 会把输入整体转义，不能写 SSML 的 `<phoneme>`。办法是换成只有一种读音的同音字：

```ts
export const pinPolyphones = (text: string) =>
  text
    .replace(/重(绘|抽|画|用)/g, '虫$1')
    .replace(/载(入|进)/g, '在$1')
    .replace(/(?<![色基冷强格语])调(色盘|画风|到|细节|参数|的|整)/g, '条$1')
    .replace(/当(需求|清单|成)/g, '荡$1')
```

- **替换前后字数不变**，提词稿能在同样的位置标出原字和拼音。
- **按词写规则，别按字。**「调」前面加否定后顾，色调、基调、强调还是念 diào。
- 支持拼音的引擎（豆包的 `<phoneme alphabet="py">`、IndexTTS、CosyVoice、MiniMax 的 `(tiao2)`）可以直接写拼音，更稳。换引擎时先用原字试，再决定哪些规则要迁移。

### 怎么确认读错了

- **ASR 听不出声调。** 读成 zhòng，Whisper 照样写「重绘」，拿它当裁判没用。
- **用同音字复现。** 把可疑的词换成只有一种读音的同音字，重新合成整句，和现有音频比，哪个一样就是哪个读音。
- **最后一道关是人耳。** 我们第一轮判定「调色盘」读对了，后来看片还是听出来念成了 diào。

## 数字、符号、缩写

- 数字的念法写进 `tts`：`9.99 美元` → `九点九九美元`，`5 秒` → `五秒`。
- 字母缩写逐个念：`NAI` → `N A I`；网址念成「点」：`example.com` → `example 点 com`。
- 型号里的点号会被念出来：`Model.3` → `Model 3`。
- 连字符、点号夹在名字里（`Mio-A`、`K Style.Male`）要单独写念法。

字幕和配音的字数不一样时，字幕的时间要按配音算。`captions.ts` 的 `alignBoundaries` 用编辑距离把字幕的每个字对齐到配音的字上，再用逐字时间戳算出每块字幕的起始帧。`captions.test.ts` 覆盖了「5 秒」念成「五秒」、跨停顿、引号不拆开这几种情况。

## 断句

两类问题：

- **配音断错了。** 「在后训练里」被念成「在后 / 训练」，原音频里「后」字被拖到 0.23 秒。这是句子本身容易误读，把句子改成「后训练阶段」，字幕和口播一起改。改完用音频时长验证：「后」是 0.13 秒，和后面两个字接近。
- **字幕切碎了。** 按字数比例分时间会切出不到 1 秒的碎块。模板的做法：按真实的逐词或逐字时间戳计时，只在标点处断句，不足 1.2 秒的块和相邻块合并，引号里的内容不拆开。`pnpm delivery-check` 会检查最短字幕。

## 英文和日文术语

换到 MiMo 这类不支持拼音的引擎后，最难的是术语。做法是一份只给这个引擎看的写法表，每条都要试出来：

| 原文 | 最后的写法 | 试过、不行的写法 |
| --- | --- | --- |
| `PixAI` | `pix ai` | 连写念糊；`piksi ai` 念法后来又改回 |
| `XL` | `叉L` | 连写被当成罗马数字「四十」；`X L` 念成「翻发」；`X-L` 念成英文字母；`叉 L` 念成「差位」 |
| `Pixiv` | `P-I-X-I-V` | `P I X I V` 念成「P.I.V.Z」 |
| `Tsubaki`（要念 ti-su-ba-ki） | `ティスバキ` | `tsu ba ki` 平均分更低 |
| `Haruka`（要念 ha-ru-ka） | `Ha-ru-ka` | 片假名常被念成 ha-lu-ka |

试写法的办法：把同一个词的几种写法放进同一句真实台词，每种录几次，听、再打分。

### 用音素模型当裁判

中文 ASR 听不准日文名和英文术语，连 Edge 念的 Tsubaki 都会被听成「四八K」。我们加了一个音素模型：

1. `wav2vec2-xlsr-53-espeak` 把念出来的术语转成国际音标（MLX 能跑，需要把 PyTorch 权重转成 safetensors）。
2. 标准读音用母语声线生成：日文名用 Edge 的 ja-JP 声线，英文词用 en-US 声线。
3. 逐个音比较相似度，1.0 是一模一样。中文母语者自然会混的音（l/r、u/ɯ、h/x）默认不扣分；需要严格的词（lo-ra 不能念成 luo-la）单独打开。
4. **只给对齐范围内的音计分。** 范围外的音不扣分，范围内每个音都算。我们一开始把两端多出来的音都当成邻字放过，漏掉了很多错。
5. 分数拦不住的，用规则拦。比如 Tsubaki 漏掉开头的 ti 时相似度还有 0.75，于是加了一条正则：术语范围内必须出现 ti，缺了算严重问题、自动重录。

质检里的阈值：低于 0.7 标橙待听，低于 0.6 自动重录；每段最多录 7 次，每句挑最好的一次。

## 读法由人定

**目标读音先问人，不要让 agent 自己按日语或英语原音假定。** 我们的 agent 默认 Tsubaki 念 tsu-ba-ki、LoRA 念「罗拉」，都和我要的不一样，白校准了一轮。先列一张术语表，写清每个词要怎么念，再让它去试写法。

## 拼接替换：试过，放弃了

想法：挑一段念得好的术语，替换到其他所有出现的地方。做法：

- 切点落在清辅音前的闭气里，结尾退出下一个字的擦音；
- 标准片段先移调，对齐原句这个位置的音高（最多 ±4 半音，共振峰不变），再对齐音量；
- 前后 12 毫秒交叉淡化，后面的逐字时间戳按长度差顺移。

技术上能做，但听感不行：同一个词在句首、句中、列举里的语调不同，对齐了音高也听得出是贴上去的。最后回到整句自然合成，靠多录几次挑好的。
